# DEMO 开发交接与里程碑

状态：开发执行顺序。范围见 [DEMO 范围](../design/demo_scope.md)；装备掉落垂直切片的唯一细则与 Q53 见 [DOC-LOOT-001](../design/loot_inventory_vertical_slice_spec.md)。旧“完整装备/通货 DEMO”叙述不构成当前实现授权。

## 1. 开工前门槛

- 文档索引中的所有权威文件存在且链接有效。
- DEMO 默认决策已写入规格，不依赖归档 GDD。
- Godot 4.7 .NET 与目标 .NET SDK 可用。
- 根 `POETower.csproj`、Entity/组件/状态机骨架和架构沙盒能编译并无头启动。

## 2. 里程碑 M0：工程与内容管线

玩家价值：无直接画面价值，但保证后续内容可由配置生产。

实现：

- 建立 Godot 项目目录、Nullable、EntityWorld、实体组件和状态机；
- 实现 CSV 读取、DTO、ContentCompiler、报告和哈希；为基础敌人和波次保留 `.tres`，并校验其稳定 ID 引用；
- 建立 AppRoot、错误页和最小 PresentationCatalog；
- 添加一组最小合法/非法测试表。

完成定义：实体架构沙盒可运行；合法目录可确定性生成并加载；每类致命校验至少有一个负例测试；Godot 无头启动到空主菜单。

## 3. M1：Godot 集成网格与 Run 骨架

依赖：M0。

实现：GameSession、固定时钟、命令队列、关卡状态机、地图定义、流场、敌人实体移动组件、冰墙验证和导航版本。流场与合法性算法保持为可独立测试的 C# 类型，由 Godot Node 持有并调度。

验收：

- Given 两条路线，When 创建冰墙，Then 50 个敌人共享新流场绕行；
- Given 最后通路，When 预放冰墙，Then 拒绝且状态不变；
- 1×和2×在相同逻辑 tick 得到相同状态。

## 4. M2：战斗与电系闭环

依赖：M1、技能/修正表。

实现：标签、Stat、条件、Modifier、效果处理器、目标选择、伤害、感电、投射物、地面效果、静电针/电弧/雷暴。

验收：三塔从表生成；感电施加、利用、消费顺序可由测试复现；浅水扩散符合规格；修改数值只改 CSV。

## 5. M3：建造与玩法场景

依赖：M1/M2。

实现：Gameplay 场景、6×4建造、6×8战区、塔/敌人/投射物表现、HUD、建造预览、出售、威力升级、暂停和2×。

验收：从主菜单进入灰盒地图，完成建塔、开波、战斗、失败和重试；连续进入10次无残留。

## 6. M4：辅助宝石、光环、冰障与图腾

依赖：M3。

实现：每塔10选5、宝石等级、复制配置事务、光环覆盖、手动冰墙构造、冰缓地面、不可受击嘲讽图腾。

验收：两座同类塔可采用不同配置；复制失败原子回滚；冰墙路线预览准确；嘲讽按持续时间且不永久锁敌。

## 7. M5：波次、金币与完整关卡

依赖：M3/M4。

实现：9波 `.tres` 数据、4普通敌人、蓝色坚韧魔法怪、首领、金币曲线、波次预告、城墙、报告。`elite_grounded`、Rare、Unique 只作为 DOC-LOOT-001 的禁用结构/视觉夹具。

验收：固定种子可完成完整胜负；波次金币偏差≤5%；首领死亡后无无用途金币；失败原因报告可解释。

## 8. M6：装备、掉落、特殊怪与恢复垂直切片

依赖：M0、M5。唯一规格：`design/loot_inventory_vertical_slice_spec.md`。该里程碑不实现所有品质的正式投放、Unique 专属效果、制作通货、出售、鉴定、容量或等级成长。

按以下顺序交接和实现：

1. 将装备基底、稀有度、词条层级/权重、掉落规则/保底、怪物词条和效果接入 CSV→JSON；基础敌人/波次 `.tres` 只引用稳定 ID，并提供文件/行/列/字段诊断。
2. 建立真实 `ItemInstance`、`Flat`/`Increased` 受控 handler、T9→T1 校验、新档六槽实例和旧定义 ID 的确定性迁移；移除两条默认 Unique 占位引用。
3. 实现命名随机流、掉落数量/品质两轴、玩家 IIR 限制、第三波魔法 T9 铜杖保底，以及蓝色坚韧魔法怪；Rare/Unique 仅夹具。
4. 实现 `TemporaryLootEscrow`、无限背包、比较/装备/卸下、局内禁用和下一局快照的真实 +12% 效果。
5. 实现波前检查点、主动退出丢弃、异常中断恢复、奖励 pending 与幂等原子提交。
6. 接入掉落落地/飞入/摘要三层表现和音效、特殊怪预告/详情、双分辨率 UI。
7. 完成 Q53 的纯 C#、内容、无头、故障注入、视觉和 100 敌人压力验收。

完成定义：Q53 十三项全部通过；胜利重启奖励存在且只存在一次；失败/主动退出永久资产不变；异常中断恢复到波前检查点；所有掉率、范围、权重和效果关系均可配置并被严格校验。

## 9. M7：反馈、平衡和交付

依赖：全部。

实现：完整 UI 状态、图标/纹理冗余反馈、统一占位美术、音效、教程提示、性能优化、缺陷清理；不以扩展元成长内容替代 M6 的 Q53 缺口。

验收：满足 `demo_scope` 完成定义和 `test_performance_spec` 预算；P0/P1为0；新玩家3分钟内能完成建造/升级/出售并能解释电系联动。

## 10. 首要删减顺序

若验证失败或制作超出范围，按顺序删减：

1. 额外的掉落装饰动画（保留落地、飞入、摘要三层语义与音效）；
2. Rare/Unique 夹具的额外表现细节（保留颜色外冗余编码和详情）；
3. `elite_grounded` 的非必要演示；
4. 非电系的燃烧地面演示；
5. 额外制作 UI 动画。

不得删减：电系三塔闭环、动态寻路/冰墙、单塔辅助配置、金币经济、DOC-LOOT-001 胜负/恢复/奖励事务、配置编译与 Q53 核心测试。

## 11. 开发约束

- 不先制作大量内容场景再补项目级通用规则。
- Node 可以承载项目规则，但配置数值必须来自 Resource/内容目录，跨实体批处理公式必须有唯一实现。
- 不把“以后可能用”当作增加框架的理由；扩展接口必须对应愿景中已确认的方向。
- 任一里程碑发现规格缺口，先更新权威文档和影响清单，再实现。
- 每个 PR/变更说明玩家可见结果、配置变更、测试、性能和未解决风险。

# POETower 核心五分钟救援切片 v1

更新时间：2026-08-16  
状态：验证完成，默认入口已于 2026-08-16 恢复；本文保留为试玩验证记录，不替代长期 `demo_scope.md`

## 1. 一句话体验目标

玩家用恰好 300 金币组成“静电针施加感电 → 电弧利用感电连锁 → 雷暴消费感电爆发”的三塔阵，在三波逐步加压的敌人中看懂联动、做出至少两次资金取舍，并在 5～7 分钟内完成一次可复玩的防守。

## 2. 为什么先做这个

当前工程已覆盖六塔、九波、导航、地形、辅助、装备、天赋和存档，但尚未用真实试玩证明最核心的电系协作是否清晰且有趣。本切片暂时缩小玩家入口，隔离最危险的体验假设；现有六塔九波资源、正式规则和自动验收资产全部保留。

## 3. 范围

### 必须

- 玩家入口只展示并允许建造静电针、电弧、雷暴三塔。
- 开局金币保持 300，三塔基础建造费合计恰好为 300。
- 只运行现有第 1～3 波；第三波清场后胜利结算。
- 战前明确说明三塔职责和推荐观察顺序。
- HUD 继续提供建造、升级、出售、暂停、1×/2×和波次摘要。
- 保留敌人感电积累、感电状态以及三类攻击的既有差异化表现。
- 新增可重复的三波无头验收，至少验证有效波数、胜利、金币和敌人清场。

### 应该

- 结算文案明确这是“核心演练”，不声称完整九波或完整战利品闭环已经完成。
- 重试回到相同的三塔三波切片。
- 九波 `wave_set_demo`、六塔 Resource、正式 `FullRunSliceSandbox` 不被修改或删除。

### 本阶段不做

- 不加入新塔、新敌人、新辅助宝石、新装备或新配置字段。
- 不调整完整九波经济，不实现掉落托管、精英词缀、音频或正式美术。
- 不重构战斗、建造、HUD、内容注册表或存档架构。
- 不把试玩假设写成长期正式范围；验证后再决定恢复或扩展内容。

## 4. 玩家流程

```text
据点
→ 核心演练战前说明（三塔 / 三波 / 300 金币）
→ 建造三塔中的任意组合
→ 第 1 波：认识感电积累
→ 第 2 波：观察电弧清杂与感电额外连锁
→ 波间用金币选择扩建、升级或出售重构
→ 第 3 波：用雷暴消费感电完成爆发
→ 核心演练胜利或城墙失守
→ 重试 / 返回据点
```

## 5. 规则与可调基线

| 项目 | 救援切片基线 | 设计意图 |
|---|---:|---|
| 初始金币 | 300 | 可一次性建齐三塔，也可集中投资形成选择 |
| 可用塔 | 3 | 消除光环、冰墙、图腾的认知噪声 |
| 波数 | 3 | 在一次短试玩中完成学习、应用、压力测试 |
| 理论累计金币 | 630 | 第三波结束前允许至少两次升级/扩建取舍 |
| 目标时长 | 5～7 分钟 | 便于重复试玩和快速迭代 |

现有第 1～3 波和三塔数值为本轮初值。第一次实现不擅自改数值；只有试玩或确定性验收给出证据后再调。

## 6. 成功指标与观察方法

面向至少 5 名第一次接触项目的玩家：

1. 3 分钟内无需口头指导完成建塔和至少一次升级、出售或重构。
2. 第一局后能说出三塔分别负责“施加、利用、消费”中的哪一步。
3. 每局至少出现两次玩家停下来比较不同金币用途的可观察决策。
4. 至少 3/5 玩家愿意立即再玩一局或主动提出另一种塔阵方案。

记录：完成时长、首次建塔顺序、每波结束塔阵、金币用途、失败波次、玩家复述、是否愿意重玩。不要在首局中解释正确答案；只记录界面自身是否传达成功。

## 7. 停止条件与后续决策

- 若玩家说不出三塔职责：优先改状态与攻击反馈、战前说明，不增加内容。
- 若总有一个塔可以单独解决全部波次：调整职责依赖、敌人构成或经济机会成本。
- 若理解联动但没有资金取舍：调整波间收入、升级费用或敌人压力。
- 若理解且有取舍但不愿重玩：检查节奏、操作摩擦和结果反馈。
- 只有四项成功指标整体通过后，才依次加回冰墙/图腾、九波节奏和局外成长。

## 8. 正常、失败与边界验收

- Given 新档进入核心演练，When 打开建造面板，Then 只出现三种电系塔且费用为 80/100/120。
- Given 第 1～2 波已经完成，When 玩家继续下一波，Then 可在波间继续建造、升级或出售。
- Given 第 3 波全部敌人清场，When 波次系统结算，Then 进入胜利且显示完成 3 波。
- Given 城墙生命归零，When 任意波仍在进行，Then 进入失败并可重试相同切片。
- Given 三塔总价等于当前金币，When 依次合法建造三塔，Then 金币恰好为 0，不出现负数或拒绝最后一次合法建造。
- Given 九波资源和完整跑通验收仍存在，When 执行原完整验收场景，Then 仍按 9 波与 2020 总金币验证，不受救援入口影响。

## 10. 首轮平衡修正（2026-08-15）

### 失败证据

真实试玩中，玩家用 300 金币把静电针、电弧、雷暴三塔全部建出，仍稳定撑不过第二波；直接感受是敌人过快、塔射程过小。量化证据：

- 两条路线长度约 1070 / 920 px。
- 移速：行尸 105、群虫 125、奔袭兽 180 px/s。
- 建造第一排中心与战区终点最小垂直间距 216 px。
- 射程：静电针 350、电弧 400、雷暴 260 px。
- 三塔合计恰好 300 金。

敌人几乎没有在塔的火力区内停留的时间，长射程优势发挥不出来，导致前两波即出现漏怪与城墙压力。

### 前后值

| 项目 | 修正前 | 修正后 |
|---|---:|---:|
| 行尸移速 | 105 | 70 |
| 群虫移速 | 125 | 85 |
| 奔袭兽移速 | 180 | 125 |
| 静电针射程 | 350 | 550 |
| 电弧射程 | 400 | 650 |
| 雷暴射程 | 260 | 550 |

### 只改速度/射程原则

本轮只调整敌人移速与三塔基础射程共六项数值。严禁同时修改 HP、伤害、攻速、波次数量/出生间隔、奖励、经济或任何核心系统。首选值 80/100/140 与 450/500/400 的回归结果为第二波城墙归零；边界值 75/90/135 与 470/520/430 虽能结束第二波，但只剩 9 点城墙，因此根据同一隔离原则继续扩大覆盖时间，得到上表最终值。

目标是“刚好稳定过第二波且墙 ≥ 50”，不追求无伤。

### 回归门槛

新增 `CoreMinuteBalanceSandbox` 无头回归场景：使用真实 `BattleRuntime`、`BuildGridController`、真实三塔与前两波，通过 `SelectTower` + `TryBuild` 用 300 金在第一排建造静电针 (2,0)、电弧 (3,0)、雷暴 (4,0)，断言三次建造均成功且金币为 0；`WaveLimit=2`、`AutoStartAndAdvance=true`、固定步推进；胜利后断言波次=2、场上敌人=0、金币 ≥ 140、城墙生命 ≥ 50。这里不要求 190 金，因为突破的敌人不会提供击杀奖励；若要求 190 金就等价于要求零漏怪、城墙无伤，与“可承受但不无伤”的目标冲突。最终确定性结果为 155 金、城墙 65，退出码 0，并纳入 `tools/verify-demo.ps1`。

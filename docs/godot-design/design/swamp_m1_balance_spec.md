## 敏感性与验收

以下连续轴均有 `-10%/0/+10%` 三点，且所有结果仍为待测：幼体数量/HP/速度；腐囊子体 HP/速度、父体 HP；泥甲 HP/速度/固定减伤；水幕护盾/延迟/回盾；坚韧 HP/速度；迅捷 HP/速度；水幕词条护盾/延迟/回盾；孢群子体 HP/速度。孢群子体数量是离散边界测试 `0/1`，不得伪装成连续 ±10%。

三档 Profile 的运行时接受区间同样尚未测量，绝不视为已通过：低配的正确反制构筑须零漏怪、火力窗余量 15%–35%，并有第二合法零漏怪构筑；目标 Profile 须零漏怪、余量 25%–45%，且至少两套零漏怪构筑；高配须零漏怪、余量 30%–55%，任何构筑的全场景支配不得超过 15%。

目标 Profile 的待测反制判据是：幼体电弧与雷暴均清场时，电弧清场时间不超过雷暴的 0.85；腐囊行尸电弧与高频感电均清场时，电弧不超过高频感电的 0.85；水幕巫徒高频感电与雷暴均清场时，高频感电不超过雷暴的 0.80。

泥甲卫士采用窄化的“结果优先”规则：雷暴必须清场；若高频感电漏怪，立即满足“高单击反制细小高频命中”的差异判据；只有两者都清场时，才比较 `雷暴 / 高频感电 <= 0.75`。这是唯一允许该语义的 M1 判据，其余三项仍使用双方清场后才可计算的时间比值。

此规则替换了旧的“无论比较构筑是否漏怪均计算 0.75 比值”。真实单泥甲卫（target / 52001）证据为：雷暴 12.467 秒清场，15 次主目标攻击、80 点生命实伤、22.5 点护甲减免；高频感电 33 次主目标攻击后仍漏怪，仅造成 32.081 点生命实伤且有 49.5 点被固定减伤吸收。因此漏怪的终止时间是右删失值，不能伪装成清场时间。未改变泥甲 HP、速度、固定减伤或最低承伤比例；回滚为删除该 guard-only `faster_clear_comparison_breach_or_ratio` 模式并恢复双方清场时间比值，随后重新测量。

性能与可读性目标同样待测：100 活跃敌人、全局活跃子体上限 32、逻辑 P95 不超过 4ms、P99 不超过 8ms、稳态热路径目标 0B、至少两个非颜色提示、波前精确预告。

## 回滚

本合同的所有 M1 初值就是精确回滚值。出现以下任一项时停止 M1 并恢复为未接入运行时的合同状态：M0 证据不匹配；确定性、配置或构建失败；触发活跃子体上限；递归生成；子体非零金币；护盾触发死亡或掉落；目标 Profile 只剩一个零漏怪构筑；同一构筑全场景领先超过 15%；敏感性断崖；性能预算失守。

运行 `tools/verify-swamp-m1-contract.ps1 -GodotPath <Godot控制台路径>` 会先读取真实 M0 迁移矩阵、M0 balance envelope 与独立 low/balanced 战报，验证 15 cases、24 sensitivity points、`148740…` 战斗兼容标识、`dd58…` 迁移矩阵身份和固定低配结果；旧 `e5ad…` 仅保留为迁移前审计锚点，不会被覆盖。随后它在第一次转换后记录完整生成配置目录哈希，并在第二次转换后比较该哈希；再以 `-warnaserror` 构建，并两次运行无头合同 sandbox。成功输出 `M0_MIGRATION_COMPATIBILITY=PASS`、`PASS NEGATIVE_CASES=17` 和稳定的 64 位合同哈希。

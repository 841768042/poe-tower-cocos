# 装备、掉落与长期成长接口

状态：接口与长期方向文档。DOC-LOOT-001 的当前需求、数值样例、恢复规则和验收，以 [装备、掉落、怪物词条与恢复垂直切片规格](../loot_inventory_vertical_slice_spec.md) 为唯一依据。

## 1. 文档边界

本文件防止长期成长方向与当前切片混淆：

| 类别 | 本文件的约束 |
|---|---|
| 现有战斗基线 | 六槽位和 `ProfileSnapshot` 是与装备系统的集成边界；它们不表示真实实例或元成长已实现。 |
| DOC-LOOT-001 | 真实实例、普通/魔法掉落、暂存、背包、提交、恢复和蓝色坚韧魔法怪，必须遵循专用规格。 |
| 长期完整 DEMO | 稀有/Unique 的正式投放、更丰富词条、等级内容和其他元成长，只能在单独改动范围和验收后启用。 |

旧文档中“所有品质均已可用”“稀有五条封顶”“传奇/制作通货已可用”等说法不再是当前实现要求或实现声明。

## 2. 永久资产与局内快照

- 永久资产保存 `ItemInstance`，而非装备定义 ID；装备槽为 `Head`、`Body`、`Hands`、`Feet`、`MainTool`、`Amulet`。
- 进入关卡时，局外装备和已允许的局外配置被编译为不可变 `ProfileSnapshot`。局内、波间和托管 UI 都不能修改它。
- 局外可比较、装备和卸下实例；装备变化仅影响下一次创建的快照。
- `TemporaryLootEscrow` 只属于 `RunState`。成功事务后才成为永久背包资产；失败、主动退出和异常恢复的行为以专用规格第 6 节为准。

## 3. 品质、词条和修正的共同语言

| 类型 | 持久化/显示约束 |
|---|---|
| `Normal` | 0 随机词条。 |
| `Magic` | 最多 1 前缀和 1 后缀。 |
| `Rare` | 最多 3 前缀和 3 后缀（最多 6），不采用旧的五条封顶规则。 |
| `Unique` | 固定专属效果，显示 `U`，不参加普通 T 级。 |

普通词条从 T9（最低）到 T1（最高）。`Flat`、`Increased`、`More`、`Override`、`Transform` 是唯一可写入内容的修正语言；任何实际效果都要映射到显式登记、类型化的 C# handler。配置不能执行表达式、脚本或任意代码。

DOC-LOOT-001 只执行 `Flat` 与 `Increased`，其余活跃效果应由校验拒绝。日后启用新修正时，应先增加 handler、校验、测试和独立范围决定，不能通过表格绕过此顺序。

## 4. 长期扩展接口（不是当前产出）

以下方向可以复用当前的数据模型，但当前切片没有正式内容或操作入口：

- `Rare` 与 `Unique` 的随机投放、固定专属效果及其平衡；
- 从区域到怪物再到物品的更高等级链，以及更多 T 级和基底；
- 增加可装备槽、角色、赛季、交易、背包容量或角色间资产；
- 出售、摧毁、鉴定、重随机、替换词条、重置天赋或其他制作通货；
- 基于装备的非 `Flat`/`Increased` 效果，以及完整天赋成长循环。

这些内容不是“默认可用功能”，也不应作为本切片测试、掉落表、起始档或胜利奖励的一部分。

## 5. 未来改动的最低门槛

任何扩展必须同时：

1. 修改 `demo_scope.md`，说明从当前切片扩展的玩家价值、排除项和验收；
2. 在内容表中配置所有范围、权重、资格和显示数据，不把数值或随机概率写死；
3. 为新数据和存档语义提供版本迁移、确定性随机策略及故障恢复；
4. 将新操作做成先验证、后写入的幂等事务，并覆盖正常、失败、重试与损坏档；
5. 更新测试性能规格和开发交接顺序，证明不会破坏现有 Q53。

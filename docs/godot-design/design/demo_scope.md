# POETower DEMO 范围与 DOC-LOOT-001 边界

状态：本文件定义当前范围层级。装备掉落垂直切片的细则见 [装备、掉落、怪物词条与恢复垂直切片规格](loot_inventory_vertical_slice_spec.md)。

## DEMO 目标

交付一个可验证的竖屏塔防闭环：玩家进入沼泽防线，使用电系三塔、光环、冰墙和嘲讽完成波次防守；DOC-LOOT-001 进一步证明一件真实装备能从掉落、托管、事务、背包到下一局效果完整闭环。

本文件不把旧的“完整装备 DEMO”当作已实现或当前切片要求。玩法、数据驱动架构、存档事务、内容制作流程、自动测试和性能预算必须分别以其权威规格和验收记录证明。

## 范围层级

| 层级 | 定义 |
|---|---|
| 现有战斗基线 | 六塔、沼泽地图和九波是代码仓库中现有的战斗内容基线与依赖；不据此宣称装备、掉落、恢复或制作功能已完成。 |
| 本切片：DOC-LOOT-001 | 只交付真实物品实例、普通/魔法掉落、蓝色坚韧魔法怪、暂存/事务/恢复、无限背包和下一局 +12% 验收链路。详情与 Q53 见专用规格。 |
| 长期完整 DEMO | 可以在本切片之后规划所有品质的正式投放、更多词条和其他元成长内容；它们不是本切片的内容预算。 |

## 可玩流程

启动 → 主菜单 → 建筑师装备/天赋 → 选择 6 个出战塔种 → 查看地图和波次摘要 → 进入关卡 → 9 波战斗 → 胜利或失败结算 → 返回据点 → 再次配置和游玩。

## 必须内容

### 地图与战斗

- 1 张完整沼泽地图。
- 6×8 战区导航网格、6×4 建造网格。
- 1 个入口、1 个城墙目标、至少 2 条可替代路线。
- 浅水、泥地、软土、不可通行地形。
- 9 波：7 个普通波、1 个精英波、1 个首领波。
- 4 种普通敌人、2 个精英词缀、1 个首领。
- 暂停、1×、2×速度。

### 出战塔种

1. `tower_static_needle`：快速施加感电积累。
2. `tower_arc`：利用感电进行连锁清杂。
3. `tower_thunderstorm`：消费感电爆发并生成感电地面。
4. `tower_voltage_aura`：持续强化电系塔阵。
5. `tower_frost_barrier`：提供可指定格的冰墙构造和冰缓地面。
6. `tower_taunt_totem`：在战区部署不可受击的持续时间嘲讽图腾。

基础携带槽为 6。数据和 UI 支持天赋 +1、装备 +1、硬上限 8，但 DEMO 内容不要求实际产出增加槽位的物品。

### 辅助宝石

- 运行时和 UI 完整支持每塔 10 个候选、单座塔最多装配 5 个、宝石最高 3 级。
- DEMO 为 6 种塔各配置 10 个候选关系；辅助宝石定义允许跨塔复用，不要求 60 个独立宝石。
- 所有候选从开始时解锁；保留 `Default/Drop/Condition` 解锁接口但 DEMO 只使用 `Default`。
- 同种塔的不同实例独立配置；提供复制同类塔配置的快捷操作并逐项结算金币。

### 装备、掉落与恢复（DOC-LOOT-001）

- 6 个装备槽：`Head`、`Body`、`Hands`、`Feet`、`MainTool`、`Amulet`；新档每槽创建一件无词缀普通实例。
- 普通为 0 词缀；魔法最多 1 前缀、1 后缀；稀有最多 3 前缀、3 后缀；Unique 为固定专属效果。只有普通/魔法装备在本切片正式生成。
- 词条 T9 最低、T1 最高；首个可获得样例为魔法 T9 铜制导能杖，`affix_lightning_damage` 的配置样例范围为 8%–12%，验收 roll 为 12%。
- 局内掉落自动飞入 `TemporaryLootEscrow`，波末最多显示 3 项摘要；胜利先幂等原子提交再展示，失败展示本局失去。
- 局内不得穿脱；局外无限背包可比较/装备/卸下；变化只在下一局 `ProfileSnapshot` 生效。
- 主动退出丢弃本局；异常中断从当前波开始前检查点恢复；胜利 pending 必须自动恢复。
- 12 个天赋节点保持既有战斗基线；本切片不新增天赋成长、制作通货或天赋制作操作。

### 局内经济与掉落

- 开局 300 金币；怪物死亡时金币立即自动到账；局末清零。
- 基础装备掉率、普通/魔法品质权重、怪物修正、玩家 IIR 和第三波保底均由配置决定；数量与品质升级为两条独立轴。
- 胜利前装备只进入临时战利品托管区；本切片没有制作通货掉落或使用路径。
- 胜利时原子提交到永久档；失败/主动退出时丢弃本局所得，不删除入场前资产；异常中断遵循波前检查点恢复规则。
- 出售返还累计建造、威力与宝石投入的 70%，受 0%–100% 最终钳制。

### UI 与反馈

- 地图/塔池选择、装备、天赋、HUD、建造、升级、辅助宝石、战利品、胜负结算。
- 建造前显示费用、占地、射程、光环、相邻关系、地形修正和合法性。
- 冰墙预览显示旧路线、新路线和断路错误。
- 敌人显示生命、感电/冻结/眩晕积累与关键状态。
- 特殊怪使用颜色加轮廓/边框/角标；常驻生命条、词条图标和桌面悬停/触屏点击详情均可读。波次预告显示特殊怪及词条信息。
- 掉落具有落地、自动飞入托管、波末/胜利摘要三层反馈，以及落地、收取、提交音效。
- 波后报告显示各塔伤害、状态贡献、控制时间、击杀和突破原因。
- 重要信息使用颜色加图标/纹理，不能只依赖颜色。

## DEMO 默认决策

- 冰墙由已建冰障塔提供：每塔独立冷却 18 秒，每塔同时 1 段，全场最多 2 段，持续 6 秒；放置不再额外消耗金币，也不使用充能。
- 怪物只因基础地形和硬阻挡重新寻路；不会主动避开燃烧、冰缓或感电地面。
- DEMO 不实现不同地面效果之间的元素反应；只实现浅水对感电/冰缓的地图联动。
- 模拟逻辑固定 30Hz，表现目标 60FPS。
- 所有随机使用显式种子；相同内容版本、配置校验和输入序列应产生相同逻辑结果。
- `Flat`、`Increased`、`More`、`Override`、`Transform` 是统一修正语言；本切片只启用受控 C# handler 的 `Flat`/`Increased`，配置不得执行任意代码。

## 范围外

- 森林和城市正式关卡；仅允许工具或测试中使用灰盒地图。
- 终局、赛季、剧情、联网、交易、排行榜、内购。
- 建筑师主动技能。
- 自由编辑怪物入口/城墙目标或由塔永久封路。
- 飞行敌人、多目标城墙、随机地图生成。
- 完整大型天赋树、全部五类塔内容、完整制作经济。
- 本切片中的实际稀有/Unique 装备投放、传奇专属效果、等级成长、出售、摧毁、鉴定、容量、制作与制作通货。
- 动态改变永久基础地形、复杂元素地面反应、敌人智能避险。
- 正式美术量产；允许统一风格的占位资源，但不可使用不可辨识的调试方块作为最终交付画面。

## 性能预算

- 目标画面：竖屏 1080×1920，60FPS；最低支持窗口以 UI 测试结果确定但不得低于 540×960。
- 逻辑：30Hz 固定模拟；2×速度通过推进更多逻辑步实现，不改变单步数值。
- 压力场景：100 个敌人、200 个活跃投射物、48 个地面效果格、12 座塔、2 段冰墙。
- 冰墙生成/消失引起的导航重算在目标开发机上单次主线程耗时目标小于 4ms，不产生连续帧尖峰。

## 完成定义

- 从新档可完成一次胜利、一次失败、一次主动退出和一次异常中断恢复流程；重启后永久数据与完成波次托管正确。
- 所有配置表通过编译期/启动期校验，无悬空 ID、重复 ID、非法范围或循环依赖。
- 核心纯 C# 规则拥有自动测试；Godot 场景具有无头烟测和手工视觉验收清单。
- 达到性能预算且没有持续增长的对象、重复信号连接或场景切换残留。
- 所有“必须内容”可由配置表调整数值和关系，不需要修改表现 Node 中的魔法数。
- 设计、配置、代码行为一致；没有引用归档 GDD 才能理解的规则。
- DOC-LOOT-001 的 Q53 十三项硬验收全部通过；不得以长期完整 DEMO 条目替代本切片验收。

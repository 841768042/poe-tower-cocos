# 装备、掉落、怪物词条与恢复垂直切片规格

状态：已确认，DOC-LOOT-001。本文件是装备实例、掉落、怪物词条、局外背包与战斗恢复在**本切片**内的唯一细则；与其他文档冲突时，按 [文档索引](../README.md) 的优先级处理。

## 1. 体验目标与范围状态

玩家在一局防守中看见可读的特殊怪和自动收取的战利品；胜利后可靠地把一件真实装备带回据点、比较并装备，下一局立即感到其效果；失败、主动退出和异常中断都不会复制或错误丢失已确认的资产。

| 范围层级 | 含义 |
|---|---|
| 现状 | 代码仓库中已有的装备槽、定义 ID、九波和存档描述是迁移输入或战斗依赖，**不表示**真实实例、四品质投放、制作通货或战斗恢复已经符合本规格。实现状态必须由测试和任务记录证明。 |
| 本切片 | 本文列出的最小端到端链路，必须完整实现并通过第 12 节的 Q53 验收。 |
| 长期完整 DEMO | 可在本切片验收后另行排期的完整稀有/Unique 投放、更多词条与等级内容；不是本切片交付物，也不得被描述成已实现。 |

### 1.1 本切片必须交付

- 真实物品实例、六槽新档实例、旧直接定义 ID 的确定性迁移、无限局外背包、比较/装备/卸下和下一局快照；
- 可配置装备基底、品质、词条层级、掉落规则、怪物词条和效果，使用 CSV 编译为 JSON，且通过严格诊断；
- 普通与魔法装备掉落、第三波教学保底、命名随机流、物品等级链、`identified` 预留字段；
- 蓝色坚韧魔法怪的正式投放，以及稀有/Unique 的数据结构和视觉夹具测试；
- 掉落落地、自动收取、托管、胜利事务、失败展示、检查点恢复与强制 pending 奖励恢复；
- 掉落三层视觉、相关音效，以及波次预告中的特殊怪信息；
- `affix_lightning_damage` 的魔法 `item_copper_conductor_rod` 验收路径：T9、12% roll 在下一局真实影响闪电塔伤害。

### 1.2 本切片明确不做

- 实际稀有装备、Unique 装备或传奇专属效果的随机投放；
- 等级成长、正式物品等级区间扩张、出售、摧毁、鉴定、容量、制作或任何制作通货；
- 多角色、赛季、交易，以及将局内装备变化即时应用到当前战斗；
- 配置表达式、脚本字符串、反射调用或其他可由内容执行任意代码的机制。

长期内容只能保留为禁用的结构、夹具或设计目标；它不能进入本切片的掉落候选、起始装备、奖励事务或 UI 可操作路径。

## 2. 术语与实例模型

### 2.1 装备槽与真实物品

装备槽固定为 `Head`、`Body`、`Hands`、`Feet`、`MainTool`、`Amulet`。槽位属于基底定义；装备、背包和托管中保存的都是物品实例，绝不能以 `item_base_id`、`unique_item_id` 或显示名充当玩家资产。

每个 `ItemInstance` 至少保存以下稳定、可序列化字段：

```text
item_instance_id
item_base_id
rarity                       // Normal | Magic | Rare | Unique
item_level                   // ilvl
identified
affixes[{affix_id, tier_id, rolled_value}]
unique_item_id?              // 仅 Unique；本切片不产生
acquired_run_id?
acquired_wave_index?
```

`item_instance_id` 全局唯一且创建后不可修改。运行时 Stat 索引、显示缓存、Godot 路径和随机对象不得写入存档。实例校验必须检查基底存在、槽位匹配、品质容量、词条池资格、层级、数值范围与排他组；未知 ID 不得被静默删除或替换。

### 2.2 品质与词条容量

| 装备品质 | 随机前缀 | 随机后缀 | 本切片生成 |
|---|---:|---:|---|
| `Normal` | 0 | 0 | 是 |
| `Magic` | 最多 1 | 最多 1 | 是 |
| `Rare` | 最多 3 | 最多 3 | 否；只保留结构/视觉夹具 |
| `Unique` | 不从普通池抽取 | 不从普通池抽取 | 否；固定专属效果结构/视觉夹具 |

魔法物品的有效随机词条总数为 1–2；稀有的有效总数由内容表决定，但绝不采用旧的五条封顶规则：上限是 3 前缀加 3 后缀，即最多 6 条。Unique 的专属效果固定，显示等级为 `U`，不参加普通词条 T 级，也不与普通随机词条混抽。

### 2.3 词条层级、首个样例与物品等级

普通词条层级从 **T9（最低）** 到 **T1（最高）**。每个层级的最低物品等级、roll 范围和权重都来自配置；T 级不使用反向编号，也不写死在 C#。

首个可验收实例由第三波教学保底产生：

| 字段 | 固定验收值 |
|---|---|
| `item_base_id` | `item_copper_conductor_rod` |
| 槽位 | `MainTool` |
| 品质 | `Magic` |
| 词条 | `affix_lightning_damage`，`Prefix`，T9 |
| T9 配置样例范围 | 8%–12% |
| 验收 roll | 12% |
| `item_level` / `identified` | `1` / `true` |

8%–12% 和 12% 是首切片内容样例与验收夹具，必须由表配置读取，不能成为代码常量。物品等级链固定为“区域等级 → 怪物等级 → 物品等级”；首切片区域和怪物均为等级 1，因此所有产物为 `ilvl 1`。物品卡同时显示 `ilvl 1` 与 `T9`；所有本切片物品均已鉴定，但 `identified` 字段为未来鉴定流程保留。

## 3. 修正语言与受控执行

内容和 UI 使用下列精确术语：`Flat`、`Increased`、`More`、`Override`、`Transform`。

| 类型 | 语义 | 本切片执行状态 |
|---|---|---|
| `Flat` | 对基础值做加减 | 执行 |
| `Increased` | 对同类 Increased 合并后的百分比修正 | 执行 |
| `More` | 在 Increased 后按乘区应用 | 不执行；活跃行必须被校验拒绝 |
| `Override` | 以显式优先级覆盖可覆盖值 | 不执行；活跃行必须被校验拒绝 |
| `Transform` | 通过命名、受控处理器改变规则或目标 | 不执行；活跃行必须被校验拒绝 |

首切片的 `affix_lightning_damage` 是 `Increased +12%`，只影响带 `skill.lightning` 标签的塔伤害。结算至少可证明“未装备”和“装备后下一局”得到不同且确定的伤害结果。

配置只能选择有限枚举、Stat、条件和已登记的处理器 ID。每个处理器由受控 C# allowlist 显式注册、具有类型化输入输出并有单元测试；CSV/JSON 不能包含可执行 C#、脚本、表达式、反射类型名或文件路径。日后启用 `More`、`Override` 或 `Transform` 时，必须先实现对应处理器、校验和测试，再允许内容表存在活跃行。

## 4. 掉落、随机与玩家可见流程

### 4.1 两条独立掉落轴

掉落数量与装备品质升级是独立轴，且所有概率、范围、权重、保底条件和数量修正都在配置中：

- 玩家 `IIR` 只影响品质升级；它不增加装备掉落次数或数量；
- 怪物 `Rarity` 与已拥有的怪物词条数同时影响掉落数量和品质升级；
- 首切片样例：普通品质权重 70%、魔法品质权重 30%、基础装备掉率 2%；稀有/Unique 的生成权重为零或被切片开关拒绝；
- 第三波结束前若本局尚未获得任何装备，教学保底生成第 2.3 节的固定魔法 T9 铜制导能杖；已获得装备时不得再生成该保底。

“概率”只说明配置样例，不能推断隐藏公式或借用其他产品的公式。数量轴先决定掉落次数，再由每一次的品质轴决定 `Normal`/`Magic`；基础、词条和 roll 之后才生成实例。金币、表现和掉落彼此不能消耗同一随机流。

### 4.2 确定性随机

每局保存 `run_seed` 与每条流的 `draw_index`。至少使用下列稳定名称：`loot.quantity`、`loot.quality`、`loot.base`、`loot.affix_select`、`loot.affix_roll`、`monster.affix`。实例 ID 从 `run_id`、稳定掉落来源和掉落序号派生，不额外消耗逻辑随机数。

新增机制必须建立新命名流；不得向已有流插入抽取。相同内容哈希、种子、检查点和输入序列必须得到相同掉落、实例 ID、词条和 roll。表现动画不得影响任何逻辑随机计数。

### 4.3 自动收取与三层反馈

玩家无需逐件点击。敌人死亡后，装备结果按以下顺序完成：

1. **落地层**：在死亡位置显示品质色、轮廓和图标的短暂掉落标记，播放落地音效；
2. **收取层**：标记自动飞入 `TemporaryLootEscrow`，播放收取音效，并在 HUD 给出非遮挡的托管增量；
3. **结算层**：波末显示最多 3 项具名摘要，其余以计数合并；胜利提交成功后展示获得物品并播放提交音效。

颜色不能作为唯一编码；品质还必须有轮廓、边框或图标。波末摘要不授予资产，不能绕过托管或提前装备。

### 4.4 托管、胜负与背包

`TemporaryLootEscrow` 仅属于当前 `RunState`，每项带有完整 `ItemInstance` 与来源波次。局内（包括波间）不能装备、卸下、使用、出售、制作或鉴定托管物品。

- **胜利**：先构造完整 `RewardCommit`，原子且幂等地写入永久档，再展示获得结果；同一 `run_id` 重试只返回同一成功结果，绝不重复发放。
- **失败**：先展示“本局失去”列表，再清除托管；入场前永久资产不变。
- **局外**：背包无容量上限，可比较、装备和卸下。装备变化只在下一次创建 `ProfileSnapshot` 时生效，绝不回写当前战斗。

## 5. 怪物稀有度与词条

### 5.1 正交模型

怪物的 `Rarity` 与 `ControlClass` 是正交字段，不能从一个字段推导另一个字段：

```text
Rarity:       Normal | Magic | Rare | Unique
ControlClass: Normal | Elite | Boss
```

| 怪物稀有度 | 词条数 | 呈现 |
|---|---:|---|
| `Normal` | 0 | 基础敌人反馈 |
| `Magic` | 1–2 | 蓝色 + 轮廓/边框/角标 |
| `Rare` | 3–4 | 黄色 + 轮廓/边框/角标 |
| `Unique` | 固定专属效果 | 暗金色 + 轮廓/边框/角标，固定名字 |

特殊怪常驻生命条和词条图标。桌面端悬停、触屏端点击均可打开详情；随机怪物词条直接显示精确效果，绝不显示 T 级；Unique 专属效果显示 `U`。波次预告必须给出即将出现的特殊怪、稀有度和已知词条，不能只在生成后才告知玩家。

### 5.2 本切片敌人内容

首个正式特殊怪为 `Rarity=Magic`、`ControlClass=Elite` 的蓝色坚韧怪，词条 `elite_hardened`：最大生命 `+60%`、移动速度 `-10%`。第二条 `elite_grounded` 保留为可配置候选：感电积累效率 `More -40%`，不得造成完全免疫。本切片仅要求坚韧魔法怪实际投放；接地词条、Rare 和 Unique 只要求结构、详情与视觉夹具验证，不能进入正式随机生成。

基础敌人和波次继续使用 `.tres`；波次资源以稳定 ID 引用怪物基底、稀有度和怪物词条。怪物词条、其权重、资格条件与效果定义走 CSV→JSON，并由内容编译器验证。

## 6. 检查点、异常恢复与奖励事务

### 6.1 文件与不可静默覆盖原则

永久档使用主档、backup 和 tmp；活跃局检查点与 `pending_reward` 为独立文件。任何写入必须先验证、写 tmp、回读验证、原子替换并保留可恢复副本。主档或 backup 损坏时不得自动用空档覆盖：必须保留诊断文件，并由玩家明确选择新档或导出诊断。

### 6.2 波前检查点

当前波进入可运行状态前创建检查点，至少保存：

- 城墙状态、局内金币；
- 塔布局、威力等级和每座塔的辅助配置；
- 当前波次索引、已完成波次的 `TemporaryLootEscrow`；
- `run_id`、`run_seed`、内容哈希与每条命名随机流计数。

未完成波内的敌人、投射物、临时状态、局内命令结果和掉落不写入该检查点。异常中断后，载入检查点并从当前波**开始前**恢复；未完成波内掉落先回滚，再用原种子、流计数和相同输入确定性重放。已完成波的托管物保持一次且仅一次。

### 6.3 退出、失败和 pending 恢复

- 玩家主动退出为 `Aborted`：丢弃本局托管与检查点，不创建 pending，不提供恢复入口；
- 城墙失败为 `Defeat`：展示失去项，丢弃托管与检查点，不写永久奖励；
- 胜利先持久化完整 `RewardCommit` 至 pending，再把奖励合入 Profile 并记录 `run_id`；只有 Profile 确认含该 `run_id` 后才能删除 pending；
- 启动时先处理 pending。未提交则自动重放，已提交则清理；玩家不能放弃、删除或跳过 pending 胜利奖励，且重放不能重新随机。

## 7. 新档与确定性迁移

新档在每个槽位创建一个 `Normal`、零词缀、`ilvl 1`、`identified=true` 的基底实例：

| 槽位 | 基底 ID |
|---|---|
| `Head` | `item_marsh_surveyor_hood` |
| `Body` | `item_reinforced_field_coat` |
| `Hands` | `item_architect_work_gloves` |
| `Feet` | `item_waders_of_haste` |
| `MainTool` | `item_copper_conductor_rod` |
| `Amulet` | `item_marsh_charm` |

不得把 `unique_storm_architect_gloves` 或 `unique_marsh_conduit_amulet` 作为新档默认装备引用。这两个历史占位 ID 不是本切片可获得的 Unique 奖励；迁移时分别转换为 `item_architect_work_gloves` 和 `item_marsh_charm` 的无词缀 Normal 实例。

旧档中直接保存的任一旧装备定义 ID 必须迁移为实例。迁移器以 `migration_version`、`profile_id`、槽位和旧定义 ID 的规范化拼接生成稳定 ID（例如其 SHA-256 截断值），并保存迁移报告；它不得使用随机流。相同输入重复迁移得到相同实例，已迁移实例不得重复创建。未知旧 ID、槽位冲突或重复实例 ID 必须失败并保留原档，不得猜测或覆盖。

## 8. 数据配置与校验契约

装备基底、装备稀有度、词条/层级/权重、掉落规则与保底、怪物词条及效果都来自 CSV 编译的 JSON；基础敌人和波次保持 `.tres`。`.tres` 只能引用稳定 ID，内容编译或启动校验必须能定位这些引用。

以下错误为致命错误，诊断必须包含文件路径、行、列、字段、稳定 ID 与错误码：

- T 级缺失、非 T9→T1 顺序、T9 不是最低层级，或 roll 范围/权重非法；
- 品质容量、词条类别、排他组、物品等级、基底槽位或 `identified` 状态非法；
- 任何掉率、数量、品质升级、权重或保底条件缺失、超界，或在代码中绕过表值；
- 本切片掉落表可生成 Rare/Unique，或第三波保底不满足“此前无装备”的条件；
- `.tres` 的稳定 ID 悬空，或魔法坚韧怪的词条/效果不合法；
- 活跃效果使用未登记、未实现或不属于本切片的 `More`、`Override`、`Transform` 处理器；
- CSV 试图传入任意可执行代码、表达式、反射类型名或未声明字段。

## 9. 依赖与实现顺序

实施必须按下列顺序进行，避免 UI 或掉落先于事务和确定性基础：

1. CSV→JSON 架构、`.tres` 稳定引用校验和可定位诊断；
2. 物品实例、修正 allowlist、品质/词条校验、T9 样例与新档/旧档迁移；
3. 命名随机流、掉落两轴、第三波保底和怪物正交模型；
4. 托管、背包、`ProfileSnapshot` 与下一局的 12% 实效；
5. 波前检查点、主动退出/异常恢复、pending 事务；
6. 掉落三层表现、特殊怪详情/预告、音效和双分辨率验收；
7. Q53 自动化、无头、视觉和压力验证。

## 10. 典型流程与边界

**正常流程**：新档带六件普通实例进入战斗；前两波未掉装备；第三波保底生成魔法 T9 铜制导能杖并自动托管；胜利后先完成幂等提交，随后玩家在据点装备它；下一局的闪电塔伤害取得 `Increased +12%`。

**失败流程**：本局已托管装备，城墙被毁；结算显示“本局失去”，托管和检查点被丢弃，入场前背包及装备哈希不变。

**异常边界**：在当前波中断；重启后不显示本波尚未完成的掉落，恢复到该波开始前的城墙、金币、塔和已完成波托管；再次重放得到相同结果。若存在胜利 pending，则先自动完成奖励提交，不能进入放弃流程。

## 11. 非目标与风险

- `Rare`/`Unique` 的容量、色彩和 `U` 是面向未来的结构验证，不承诺本切片有正式产出；
- 现有旧规格中的所有品质正式投放、传奇效果、制作通货、出售或容量若仍被任何旧文档提及，只能视为长期完整 DEMO，不能据此扩展本切片；
- 本规格不采用任何商业作品的专名、数值公式、资源或受保护表达；数值样例是本项目可调内容；
- 波前恢复要求战斗输入和随机消费确定性。若现有局内命令不能重放，必须先补齐命令记录/重放能力，不能以“尽量恢复”降级。
